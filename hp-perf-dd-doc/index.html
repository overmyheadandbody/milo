C2 Homepage — Performance Enhancements

Impact of the sr-perf-dd Milo branch plus the paired UPP consumer change on the adobe.com C2 homepage. Numbers come from throttled A/B testing, the network waterfall, and the CDP scroll/CPU harness.

Shipped enhancements

Each card leads with the real-world benefit and the number behind it.

Load speed & data CPU / responsiveness Scroll & battery Rendering health ✅ Design consulted — approved 👥 Design awareness
01Defer hero video + start autoplay on first frame MWPW-203828MiloDesktop
👥Design awareness. On slow connections the carousel's first auto-advance is held back until the hero video is ready, so the opening slide stays on screen a little longer.
The desktop hero appears ~5 seconds sooner — the single biggest win. LCP 11.4s → 6.1s.

The 2.4 MB marquee video used to download immediately and its first frame became the "largest content," delaying it to ~10s. Now the video loads lazily (preload="none") and the autoplay timer, progress bar, and next-slide preload wait for the hero's first frame — so the page can show the heading first instead of waiting on the video.

Improves: LCP (load speed), TBT
02Load only the slide images people see first MWPW-203829MiloMobile · Desktop
Phones download 3 fewer hero images upfront (5 → 2), and desktop loads none of the mobile-only images. Faster first paint and less mobile data; the rest load only as slides advance.

The carousel slides are stacked on top of each other, which defeats the browser's built-in lazy-loading — so every slide image used to download at once. Now only the first visible slide loads immediately; the others are held back and fetched when their slide is about to show, freeing bandwidth for the content that appears first.

Improves: LCP (load speed), data downloaded
03Stop downloading video posters that are never shown MWPW-203830MiloMobile · Desktop
Phones stop fetching 5 desktop/tablet poster images they never display. Together with #2, first-load image data drops 99 KB on mobile and 273 KB on desktop.

The page ships a marquee for each screen size, so the desktop and tablet posters were downloading on phones (and vice versa). Now a hidden viewport's poster is only fetched if and when its video actually plays.

Improves: LCP (load speed), data downloaded
04Prioritize the right hero image per screen size MWPW-203831UPPDesktop
Desktop stops downloading a 257 KB image it never displays (the mobile hero) — total image data drops 41% (1298 → 769 KB). Ships independently on the UPP side.

UPP's loading logic used to grab the first image on the page and mark it high-priority — which on desktop was the hidden mobile hero, the single heaviest asset. Now it picks the image for the current screen size and skips the ones that won't be shown.

Improves: data downloaded, hero image priority
05Remove the carousel's biggest CPU hotspot MWPW-203832MiloDesktop · Mobile
The carousel and window-resizing no longer stall the main thread. Resizing now triggers 1 layout recalculation instead of ~12, and autoplay runs with none. Result: less CPU work, fewer dropped frames.

The layout code repeatedly measured and then changed the page in the same pass, forcing the browser to recompute the layout over and over. It now measures everything first, writes once, skips the write when nothing changed, and batches resize work — so the same visual result costs a fraction of the work.

Improves: CPU / TBT, frame rate
06Make Brand Concierge cheap to resize MWPW-203833MiloDesktop · Mobile
Resizing the window is ~3× cheaper on the CPU (177 ms → 57 ms of main-thread work), so the page keeps responding to taps and clicks. It's below the fold, so this helps responsiveness (INP/TBT), not load speed.

Every resize event re-measured and re-flowed every prompt pill immediately, piling up layout work and freezing the main thread during resize and phone rotation. The work is now batched to once per frame.

Improves: INP / TBT / CPU  (not LCP)
07Turn off the Lenis smooth-scroll library on phones MWPW-203834MiloMobile
✅Design consulted — approved. Lenis (smooth scrolling) was a design request; Design confirmed it's OK to turn it off on phones (returning them to the browser's native scroll).
Mobile scrolling runs on the browser's native path: ~18 KB less to download, up to ~47% less CPU work while scrolling, and 83% fewer layout recalculations (113 → 19). Smoother scroll and better battery on phones.

On phones, Lenis added a download and moved scrolling onto the main thread, turning a single lightweight update into ~306 layout recalculations per scroll. Native scroll runs off the main thread and costs nothing extra to ship. (Scroll-driven animations still work via a native fallback.)

Improves: INP / frame rate / CPU, data downloaded
08Skip Lenis on low-end and Windows devices MWPW-203835MiloDesktop · Laptop
✅Design consulted — approved. Design confirmed it's OK to skip Lenis on low-end and slow/slower Windows machines, trading smooth-scroll feel for stability on weaker hardware.
Weaker devices skip the Lenis download entirely (~18 KB / ~5.3 KB gzip) and fall back to native scroll — graceful degradation with stable frame rate where smooth-scroll would otherwise stutter. Also honors Save-Data and reduced-motion.

Smooth-scroll is heaviest exactly where the device is weakest. The page now checks device memory and CPU cores and skips Lenis on low-end hardware — biasing harder on Windows, where integrated-GPU compositing is the real cause of scroll jank (so it's skipped if either memory or cores are low, vs. both elsewhere). Users who set Save-Data or reduced-motion always get native scroll.

Improves: frame rate / graceful degradation, CPU, data downloaded
09Stop Lenis from running when nobody is scrolling (desktop) MWPW-203836MiloDesktop
Desktop reclaims ~8.5% of a CPU core that Lenis used to consume non-stop, even when the page was idle — saving battery. Scrolling feels exactly the same.

Lenis's default keeps an animation loop running continuously. It now runs only while you're actually scrolling and stops the moment scrolling ends. Pure engineering change, no perceptible difference.

Improves: CPU / battery, frame rate
10Clean up misused GPU rendering hints MWPW-203837MiloDesktop · Mobile
Frees GPU memory and removes rendering work that could cause stutter on low-end devices — 3 always-on or misapplied will-change hints removed or scoped to when they're actually needed. No visual change.

will-change tells the browser to keep an element on a dedicated GPU layer. Left on permanently it wastes GPU memory, and on properties that can't be GPU-accelerated it only adds cost. The hints are now applied only during the interaction that needs them (e.g. while dragging), not all the time.

Improves: frame rate, GPU memory

Planned next step

Part of this batch, not yet implemented — documented here with its expected effect.

11Rework the grid parallax to animate a transform MWPW-203838PlannedMiloDesktop · Mobile
Expected: smoother scroll and stable frame rate on the grid parallax, with lower CPU during scroll — removes a layout recalculation that currently runs on every scroll frame.

The .parallax-scale-down-grid effect currently animates padding-inline / --grid-max-width as you scroll. Those are layout properties, so the browser has to recompute the page layout on every frame of the scroll — expensive and prone to jank on weaker devices. Reworking it to animate a transform (scale) instead moves the work to the GPU compositor, which needs no layout recalculation.

Improves: frame rate, CPU (during scroll)
